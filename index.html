How it works

Engagements

Pay for outcomes,
not hours.

Each engagement runs for a fixed monthly fee, agreed in a written proposal. Your objectives set the work, and the fee changes only by written agreement.

01 / Modernise

Modernisation

Move a legacy system or module to a modern platform, with the old path kept as a fallback until the new one is proven.

Example objective: “Retire the old billing module by the end of Q2.”

You receive

  • A migration plan with milestones and success measures
  • Signed releases with test evidence
  • The old path retired once the new one is proven
02 / Deliver

Product delivery

Deliver the objectives on your product roadmap, one signed release at a time.

Example objective: “Let business customers change their plan themselves.”

You receive

  • Acceptance criteria agreed before work starts
  • Working features in your systems
  • A monthly report on progress, cost and risk
03 / Run

Run and maintain

Keep software, integrations and dependencies working and up to date. No software team? We host, run and fix it for you.

Example objective: “Keep our payment integrations working.”

You receive

  • Security fixes and upgrades
  • Monitoring, with response times agreed in the proposal
  • Hosting and backups, if you need them

Accountability

Agents do the work.
A person signs for it.

Every release carries the signature of a named senior architect. The signature states that the change was reviewed, tested and is safe to ship, and the architect answers for it.

Zigmas Slušnys

What a signature confirms

  • The change does what the objective requires, against written acceptance criteria
  • All automated tests pass, and the evidence is attached
  • Security checks pass, with no new known vulnerabilities
  • A rollback plan exists and was checked
  • The decision is recorded, with the name and the date

Before we begin

Questions worth
asking early.

Procurement, security or commercial questions not covered here? Email hello@intervencija.eu

Where do our code and data go?

Each client’s work runs in a separate environment with its own credentials. The proposal and the data processing agreement name every AI model provider and other service that processes your code or data, and where it is based. Code and documentation are delivered into your repositories.

What should we share in the first message?

The result you need, a short description of the systems involved, and any important timing. There is no need to share source code, customer data or detailed internal documents at this stage.
